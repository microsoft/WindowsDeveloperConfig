# Windows Dev Config — contributor guide

> 👋 **Just want to run it?** See the [Windows Dev Config README](../windows-dev-config/README.md).

See also the repo-wide [Developer Guide](./development.md) for CI, testing, and the signed/source layout shared by every flow.

Source of truth for this flow is `src/windows-dev-config/`. The copy at the
repository root is the Authenticode-signed release copy, regenerated by the
sign pipeline — don't edit it directly. See
[`src/docs/development.md`](./development.md#repo-layout-signed-vs-source).

Run `.\src\tests\calm-os\module-path-checks.ps1` from the repository root on
Windows with PowerShell 7 installed to check cross-edition module loading and
signature verification without applying setup. `src\tests\calm-os\winget-source-checks.ps1`
checks WinGet retry/fallback behavior with simulated package operations,
without changing the machine; run it in both Windows PowerShell 5.1 and
PowerShell 7.

`src\tests\calm-os\pwsh-discovery-checks.ps1` checks MSI, MSIX, and portable
PowerShell discovery and handoff without installing software. Run it in both
Windows PowerShell 5.1 and PowerShell 7.

`src\tests\calm-os\skip-checks.ps1` checks `-Skip` with simulated registry,
WinGet, WSL, and PowerShell 7 calls: the accepted ids, validation before
anything runs, forwarding through elevation, relaunch, and reboot resume, and
that skipped items are never checked or changed. Run it in both Windows
PowerShell 5.1 and PowerShell 7.

`src\tests\calm-os\restart-checks.ps1` checks restart handling with simulated
WSL, task scheduler, console keys, and `shutdown.exe` calls: Ubuntu waits for
the restart and phases that can wait run last; at a console setup asks
**Restart now? [Y/n]** and only Y or Enter restarts, while earlier keys, no
answer, no console, and `-NoRestart` restart nothing; `-RestartWhenNeeded`
registers the resume task and restarts after its countdown, or at once without
a console; a cancelled countdown, or a restart request that's missing,
unreadable, or failed to save, restarts nothing; a resumed run without evidence
of a restart exits at once without pausing or elevating; and 3010 reaches
callers. Run it in a VM or sandbox, in both Windows PowerShell 5.1 and
PowerShell 7. Validate the real behavior there too: restart now (answer Y, then
run again; or let the `-RestartWhenNeeded` countdown run out), restart later
(answer N, or cancel the countdown, then restart and run again), and never
restart (`-NoRestart`, or no console: the run ends with 3010 and changes
nothing further).

## File layout

| File | What it is |
| --- | --- |
| `bootstrap.ps1` | Remote entry point: elevation, verified downloads, protected installation, and launch. |
| `setup-full.ps1`, `setup-standard.ps1`, `uninstall.ps1` | Fixed-action wrappers that verify and call the signed bootstrap. |
| `dev-config.ps1` | The orchestrator shared by every workload: elevation, shell selection, run lock, logging, phases, and summary. |
| `workloads/<name>.ps1` | A workload definition: its display name, supported actions, and phase list. `devconfig` is the default. |
| `steps/_workload.ps1` | Loads and validates workload definitions, and passes each phase its parameters and step selection. |
| `steps/_step-runner.ps1` | The check/apply/verify engine, the tally, and the flag reporting. |
| `steps/_security.ps1` | Signature and directory-permission checks. Its signature is verified before loading unless `-AllowUnsigned` is used. |
| `steps/_*.ps1` | Shared helpers: elevation, reboot and resume, winget, registry, Terminal settings, retry, process execution, console. |
| `steps/<phase>.ps1` | One file per phase, each exporting a single `Invoke-<Name>Phase` function. |

## The phases

`Full` runs all 11 phases in order; `Partial` skips Edge and uses [fewer settings](../windows-dev-config/README.md#setup-actions). WSL + Ubuntu runs last, so a restart WSL needs never holds up the other phases.

Setup doesn't restart Windows from inside a step. A step that can only finish after a restart calls `Set-DevConfigStepRestartPending` instead of failing, and steps that depend on it do the same, as `WslUbuntu` does for `WslComponents`; phases that can wait for a restart run last in every workload, so nothing else waits behind one. The run then finishes, saves `<workload>-restart.json` next to `dev-config.ps1` (written atomically and read back), and exits with 3010. Running again is the resume: that file tells the next run whether Windows restarted in between, so WSL isn't reinstalled while its restart is still pending, and a platform still inactive after the restart stops the run instead of asking for another one. The file is kept until every step that waited verifies, so a run that skips, flags, or doesn't include them keeps it. A file that can't be read, or a boot time that can't be read, is `Unknown`: the run says so, leaves the file alone, and doesn't restart Windows. Only `dev-config.ps1` restarts Windows, only with a request that saved and read back as pending, and never with `-NoRestart`. By default `Request-DevConfigRestart` in `steps/_reboot-resume.ps1` asks **Restart now? [Y/n]** when there's a console and restarts on yes, scheduling nothing; with `-RestartWhenNeeded`, `Suspend-DevConfigForReboot` registers the resume task and restarts after a cancellable countdown, or at once without a console. Both restart through `Restart-DevConfigWindows`, without `/f`. A `-Resumed` run continues only when the file shows Windows restarted; otherwise it exits before elevation, without pausing.

| # | Phase | # | Phase |
| --- | --- | --- | --- |
| 1 | Getting ready | 7 | Fonts |
| 2 | Packages | 8 | Windows Terminal |
| 3 | System settings | 9 | PowerShell profile |
| 4 | File Explorer tweaks | 10 | GitHub Copilot (best-effort) |
| 5 | Taskbar, search & start tweaks | 11 | WSL + Ubuntu |
| 6 | Microsoft Edge tweaks |  |  |

Adding a phase means adding one file and one entry in a workload's phase list. Adding a step to an existing phase means one `New-DevConfigStep` call. Keep every step's check cheap and side-effect free — it runs on every invocation, including the fast path where nothing needs doing.

Step and setting names, phase file names, and package WinGet ids are also the [`-Skip` ids](../windows-dev-config/README.md#leave-items-out) callers pass, such as `registry-system/Sudo`. Renaming one breaks those callers; `skip-checks.ps1` lists every id and fails when one changes. A step that applies a setting someone can skip on its own, like `terminal/DarkTheme`, lists that setting with `-SettingIds` and leaves it alone when it's skipped. Phases build their step lists before any slow preparation and call `Test-DevConfigStepsToRun` first, because `-Skip` validation builds every phase's steps without running them.

Run the isolated WSL probe checks from the repository root in Windows PowerShell 5.1 and PowerShell 7; they do not install WSL:

```powershell
.\src\tests\calm-os\wsl-query-checks.ps1
```

## Publishing a release

1. Complete a public-content and privacy review of source, documentation, examples, fixtures, generated reports, and release notes.
2. Sign and publish the payload files as commit A.
3. Set `$payloadRef` to A's full SHA in the source launchers: `setup-full.ps1`, `setup-standard.ps1`, `uninstall.ps1`, and `Workloads/winui/setup.ps1`.
4. Sign those updated launchers and publish their signed copies as commit B. Do not edit them after signing.

Include all AI `Workloads/**/setup.ps1` launchers in the same payload pinning
and signing cycle, along with the WSL Comfort launcher `wsl-comfort/setup.ps1`.
That launcher downloads `wsl-comfort/` from A directly instead of calling bootstrap;
point `https://aka.ms/devconfig/wsl-comfort/setup.ps1` at the signed repository-root
`wsl-comfort/setup.ps1`.

The launchers in B download bootstrap and its payload from A. Short URLs keep pointing at the launchers on `main` — publishing a new launcher doesn't change the payload commit an older launcher uses. Direct bootstrap calls with a branch or tag still use Git ref discovery.

## Adding a workload

A workload reuses the shared engine, so it only describes *what* to set up. Elevation, signature checks, the protected install, PowerShell 7, WinGet recovery, retries, logging, the run lock, and the summary all come from the files above, fixed once for every workload.

1. Add `workloads/<name>.ps1`. It takes `-Action` and returns a hashtable; it must not change the machine.
   [`workloads/winui.ps1`](../windows-dev-config/workloads/winui.ps1) is the model to copy.

   | Key | Required | Meaning |
   | --- | -------- | ------- |
   | `Name` | Yes | Display name, used as "`<Name>` setup complete." |
   | `Actions` | Yes | Supported `-Action` values. Other actions are rejected before anything runs. |
   | `Phases` | Yes | Ordered phases. Each has `File`, `Function`, and `Title`, plus optional `Parameters` (passed to the phase function) and `Steps` (run only these steps of a shared phase). |
   | `MinimumOSVersion` | No | Oldest supported Windows version, checked before elevation. |
   | `SetupNote` | No | Added to the opening line, for example the one restart or a large download. |
   | `UninstallWarning` | No | Shown in yellow before cleanup starts. |
   | `Notes` | No | Lines printed after the summary, such as a next step. |

2. Reuse phases wherever possible. Install packages by name through the packages phase: add any new package to
   the catalog in [`steps/packages.ps1`](../windows-dev-config/steps/packages.ps1) once, and every workload can list it. Pick
   individual steps from a shared phase with `Steps`, as WinUI does for Developer Mode and the WinUI templates.
   Only write a new phase file for work no phase covers, like [`steps/visual-studio.ps1`](../windows-dev-config/steps/visual-studio.ps1).
3. Add a signed entry point at `src/Workloads/<name>/setup.ps1` by copying
   [`Workloads/winui/setup.ps1`](../Workloads/winui/setup.ps1) and changing only `-Workload`.
4. Test from a clone without signing: `.\src\windows-dev-config\dev-config.ps1 -AllowUnsigned -Workload <name>`.
   After the sign cycle, point a short link such as `https://aka.ms/devconfig/<name>/setup.ps1` at the
   repository-root `Workloads/<name>/setup.ps1`.

The engine checks a workload in three stages, and any problem stops the run with a message:

- When it loads the definition: unknown keys, malformed values, the action, and the minimum Windows version.
- Before anything changes, when `-Skip` is passed: every id must be one of the workload's settings, steps, or packages.
- Before the first phase runs: phase files, functions defined in those files, and parameters, including
  required parameters the workload doesn't set.
- When a phase runs: package names and `Steps` names.
